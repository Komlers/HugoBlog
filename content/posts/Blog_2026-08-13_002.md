## 起因。

昨晚我重启进我的 Fedora 44 KDE Plasma Desktop Edition 环境，打算装个WPS Office来着。（也不是Libre不好用，就是有点难用。）

然后我从 [WPS官网](https://www.wps.cn/product/wpslinux) 下载了 `.rpm` 软件包，打开终端执行 `sudo dnf install` 安装的时候，甩给我一个报错：

![87D51757380917AF8084351B39394518.png](https://img.danevan.top/image/pic/260813/87D51757380917AF8084351B39394518.png)

核心问题在于：

```bash
>>> Status code: 404 for https://mirrors.tuna.tsinghua.edu.cn/fedora/releases/44/Everything/x86_64/os/repodata/repomd.xml (IP: 198.18.0.9) - https://mirrors.tuna.tsinghua.edu.cn/fedora/releases/44/Everything/x86_64/os/repodata/repomd.xml
```

```bash
下载仓库「baseurl」的元数据失败（https://mirrors.tuna.tsinghua.edu.cn/fedora/releases/44/Everything/x86_64/os/：「fedora」）：Usable URL not found
```

当时我就懵了，怎么爆404了。我还以为是我梯子忘关什么的导致代理出错，但排除了这一部分的可能后，还是爆404。

确实，我第二天早晨去看了 [TUNA镜像站同步状态](https://mirrors.tuna.tsinghua.edu.cn/status/)，果真在同步：

![897BD41A54F9EB5151B0BC7D4703E793.png](https://img.danevan.top/image/pic/260813/897BD41A54F9EB5151B0BC7D4703E793.png)

但是很诡异的一点是，上一次同步成功是一天前，TUNA一般是每隔6个小时左右就 `rsync` 一次，即使镜像有1个T，几分钟十几分钟就能同步完。

而至少我发现的，Fedora仓库已经同步了快半天了（22:00到次日10:00），这很奇怪，所以我就去 [TUNA的GitHub](https://github.com/tuna/issues) 开了个Issue： [Fedora44镜像源dnf获取元数据报404](https://github.com/tuna/issues/issues/2578)

![Snipaste_2026-08-13_16-15-03.png](https://img.danevan.top/image/pic/260813/Snipaste_2026-08-13_16-15-03.png)

## 成果。

最终也是有老哥给我comment了：

![Snipaste_2026-08-13_16-17-02.png](https://img.danevan.top/image/pic/260813/Snipaste_2026-08-13_16-17-02.png)

> 这是因为 Fedora 44 的仓库数据被上游误删除，导致下游镜像站也在同步时删除了这些数据。目前正在重新同步中。

所以应该不会很久，TUNA镜像站的Fedora仓库就能恢复正常。
