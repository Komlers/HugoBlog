## 1 - 前情

是这样的，我今天凌晨心血来潮来收拾这个博客，主要就是拿AI来配置美化一下这个博客。我想着既然都收拾博客了，那就顺便把我的个人网站也一块儿收拾一下吧。

这边给博客加到这个 [Vercount](https://www.vercount.one/) 网站访问统计工具的时候，我就顺便一块给主站也加上了。

然后我就让DeepSeek把这个Vercount的数据显示加一层处理，转换为千分制（123,456,789）。

DeepSeek给我填充的这段代码：

```javascript
// ============================================
// 7. Vercount 浏览量千分位格式化
// ============================================

(function initVercountFmt() {
    var el = document.getElementById('vercount_value_site_pv');
    if (!el) return;
    function fmt() {
        var n = el.textContent.replace(/,/g, '').trim();
        if (/^\d+$/.test(n)) el.textContent = Number(n).toLocaleString('en-US');
    }
    new MutationObserver(fmt).observe(el, { childList: true, characterData: true, subtree: true });
    fmt();
})();
```

乍一看还挺好。加上我对JavaScript的了解还不多，我就直接给他放行了

> [!NOTE]
> 记住这个，后面要考

然后我就 `git push` 上去了，然后打开浏览器测试效果，很完美，很迅速，很好用。

### 2.3 - 真相大白

我先回去调了一下Git提交记录：

![e4ed709e234321c86e6b47e3686f9b2e.png](https://img.danevan.top/image/pic/260811/e4ed709e234321c86e6b47e3686f9b2e.png)

发现对于JavaScript的改动只有那一段代码。排除Vercount服务API的问题外，能出错的地方只有这里了。

我就直接回去质问DeepSeek了：

> **我：**
> 
> 我操！！！出大问题了！！！！！今天凌晨不是加了个Vercount计数吗，我凌晨测试的时候一切正常，但是今天白天直到现在，在Edge上会有内存泄漏！泄露速度大概100MB/s，Chrome也漏，但是慢一些，10MB/s以内。并且加载主页面浏览器就会卡死，快帮我看看什么情况！

然后DeepSeek“认真”思考了一下，给了我一个想骂人的答案：

> **DeepSeek-V4-Flash：**
> 
> 这就是我之前埋下的雷！问题在 `info.js` 里第 7 节的 `MutationObserver` ——它在回调里对元素 `textContent` 赋值，而 `characterData` 又会再次触发观察器，形成**无限反馈循环**，导致内存暴增、页面卡死。让我确认当前代码再修复。
